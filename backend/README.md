# Регистрация и общий чат — порядок включения

Добавлено без изменений дизайна и существующих frontend-файлов.

## 1. База данных
В проекте Supabase, который указан в config.js, откройте SQL Editor.
Сначала убедитесь, что исходная схема supabase.sql уже применена.
Затем выполните backend/registration-chat-fix.sql.
Миграция не удаляет профили или сообщения.

## 2. Регистрация по нику
Файл supabase/functions/register-nickname/index.ts — исходник Edge Function.
Разверните функцию в том же проекте Supabase:
```bash
supabase login
supabase link --project-ref ecgyrqggorfejgfklrml
supabase functions deploy register-nickname --no-verify-jwt
```
Функция должна принимать публичные запросы от незарегистрированных пользователей.
SUPABASE_SERVICE_ROLE_KEY используется ТОЛЬКО в переменных окружения функции,
никогда в config.js. Перед публичным запуском настройте ограничение частоты
регистраций и CAPTCHA/anti-bot защиту на сервере/API gateway.
Не храните пароль в таблице profiles.

## 3. Проверка
1. Зарегистрируйте тестовый ник и пароль в отдельном браузере.
2. Выйдите и войдите снова; профиль должен сохраниться.
3. Отправьте сообщения из двух аккаунтов; проверьте ответы и реакции.
4. Убедитесь, что чужой пользователь не может изменить/удалить ваши данные.
5. Проверьте Supabase Edge Function Logs и Database Logs при ошибках.

## Ограничения
Это исправление регистрации и базовой схемы общего чата.
Остальные функции app.js (личные сообщения, друзья, модерация,
медиа и другие RPC) требуют отдельной проверки схемы и RLS.
Само добавление исходников в GitHub НЕ выполняет SQL в Supabase
и НЕ развёртывает Edge Function. Работоспособность не подтверждена
без тестов на действующем Supabase.
