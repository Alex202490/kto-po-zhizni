# Подключение настоящего backend — v15

Фронтенд уже умеет работать с Supabase. Пока `config.js` содержит заглушки, сайт автоматически остаётся в демо-режиме.

## Что заработает после подключения
- регистрация по e-mail и паролю;
- вход/выход и сохранение сессии;
- автоматическое создание профиля;
- реальные пользователи из PostgreSQL;
- загрузка аватара и обложки до 5 МБ (PNG/JPG/WEBP);
- общий realtime-чат;
- список онлайн через Presence;
- редактирование ника и «О себе»;
- короны/донатерские статусы читаются из базы.

## 1. Создать проект Supabase
Создайте пустой проект Supabase.

## 2. Создать таблицы и правила
Откройте SQL Editor и выполните файл `supabase.sql` целиком.

## 3. Вставить публичные ключи
В `config.js` замените:

```js
supabaseUrl: "PASTE_SUPABASE_PROJECT_URL_HERE",
supabaseAnonKey: "PASTE_SUPABASE_ANON_KEY_HERE",
```

на Project URL и anon/publishable key вашего проекта.

**Никогда не вставляйте service_role key в `config.js` или любой браузерный файл.**

## 4. Auth
В Supabase Auth → URL Configuration укажите адрес опубликованного сайта как Site URL. Если подтверждение e-mail включено, новый пользователь сначала подтверждает письмо, затем входит.

## 5. Проверка
Откройте сайт в двух разных браузерах/профилях, зарегистрируйте двух пользователей и отправьте сообщения. Сообщения должны появляться realtime, а оба пользователя — отображаться онлайн.

## Следующий backend-этап
Личные сообщения, друзья, постоянные реакции/ответы, уведомления и платежный webhook будут отдельной миграцией. Донатерские поля специально защищены от изменения из браузера.


## v17: вход без email/SMS
Интерфейс использует ник + пароль. Внутри Supabase Auth создаётся технический email, вычисляемый из ника. Пользователь его не видит. Для мгновенной регистрации в Supabase Dashboard нужно отключить обязательное подтверждение email (Confirm email). Восстановление пароля без привязанного email/телефона недоступно.


## v18
Регистрация ник+пароль выполняется через Edge Function `register-nickname`. Функция серверно создаёт подтверждённого Auth-пользователя, после чего браузер выполняет обычный вход. Email/SMS пользователю не требуются.
